# 4. Financing Structure Analysis

### The Discrepancy:
$$\text{Promoter Margin (₹2,38,235)} + \text{Sanctioned Loan (₹13,50,000)} = \mathbf{₹15,88,235} \neq \mathbf{₹15,00,000} \text{ (Total Project Cost)}$$

### Forensic Code Root Cause:
1. In `calculateStandUpIndia()` ([`lib/finance/schemes.ts`](file:///D:/dev_classroom/ruralCred_Advisor/lib/finance/schemes.ts#L284-L287)):
   ```typescript
   const marginPercent = 15;
   const projectCost = Math.round(sanctioned / 0.85); // 13,50,000 / 0.85 = 15,88,235
   const promoterContrib = projectCost - sanctioned;  // 15,88,235 - 13,50,000 = 2,38,235
   ```
2. In `generateUnifiedBusinessPlan()` ([`lib/finance/plan.ts`](file:///D:/dev_classroom/ruralCred_Advisor/lib/finance/plan.ts#L519-L522)):
   ```typescript
   return {
     ...
     totalProjectCost: projectCost, // req.projectCost = 15,00,000
     promoterMargin: promoterMargin, // chosenScheme.promoterContribution = 2,38,235
     promoterMarginPercent: promoterPct, // 15%
     requestedLoanAmount: sanctionedLoan, // 13,50,000
   };
   ```
3. **Explanation:**
   - There is a **mismatch between the independent project cost and the scheme-derived margin contribution**.
   - If the project cost is **₹15,00,000** and the scheme mandates a **15% promoter margin**, the correct values should be:
     $$\text{Promoter Margin (15\%)} = 15,00,000 \times 0.15 = \mathbf{₹2,25,000}$$
     $$\text{Sanctioned Loan (85\%)} = 15,00,000 \times 0.85 = \mathbf{₹12,75,000}$$
     $$\text{Total Project Cost} = ₹2,25,000 + ₹12,75,000 = \mathbf{₹15,00,000}$$
   - Instead, `calculateStandUpIndia` fixed the loan at ₹13,50,000 and scaled the project cost *upward* to ₹15,88,235, but `generateUnifiedBusinessPlan` retained the original ₹15,00,000 project cost header while taking the ₹2,38,235 margin from the scheme, causing the $₹88,235$ balance discrepancy.

# 7. Single Source of Truth Assessment

The PDF generator **does consume the same `UnifiedBusinessPlan` data object** as the Business Plan UI. 

The contradictory values occur because:
1. **Financial Coupling Bug in `plan.ts` / `schemes.ts`:** `generateUnifiedBusinessPlan` mixes the user's fixed `projectCost` (₹15,00,000) with `chosenScheme.promoterContribution` (₹2,38,235), which was calculated from a floating $₹13.5\text{L} / 0.85 = ₹15.88\text{L}$ base.
2. **Template Hardcoding in `pdf.ts`:** Line 68 of `pdf.ts` contains static text instead of checking dynamic registration state.
3. **Statutory Scheme Rate Override:** Stand-Up India statutorily uses 8.5% (concessional commercial MCLR spread for loans > ₹10L) rather than the standard 8.0% term loan rate used for micro-loans <= ₹10L.

# 9. Final Verdict

### **MULTIPLE ISSUES**

### Detailed Justification:
The audit revealed two distinct root causes:
1. **Financial Calculation Coupling Bug (`lib/finance/plan.ts` & `lib/finance/schemes.ts`):** When Stand-Up India is selected for loans > ₹10L, the scheme calculator applies a 15% margin requirement by computing $\text{projectCost} = \text{loan} / 0.85 = ₹15,88,235$ and $\text{margin} = ₹2,38,235$. `generateUnifiedBusinessPlan()` takes `promoterMargin = ₹2,38,235` from the scheme but keeps `totalProjectCost = ₹15,00,000` from the request, breaking the accounting identity $\text{Margin} + \text{Loan} = \text{Project Cost}$.
2. **Hard-coded Static String (`lib/export/pdf.ts`):** Line 68 statically prints `"Statutory Status: Udyam MSME Registered"` without evaluating `profile.hasUdyamRegistration` or the checklist state.
